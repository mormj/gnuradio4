# GNU Radio 4 review

Accept the normal request: **Review PR #27 in gnuradio4-blocks as a maintainer.** The superbuild containing this file's `.review/` directory is the framework home. Resolve links relative to this file. The reviewer supplies setup and generates the contract; do not ask the user for routine SHAs, stack parents, SDK paths, commands, dimensions, depth or contract fields.

1. Parse component, review profile and unusual scope constraints. Use [maintainer](profiles/maintainer.yaml) for a merge decision or an unspecified profile, [developer](profiles/developer.yaml) for implementation behavior, [security](profiles/security.yaml) for adversarial/trust analysis, and [thorough](profiles/thorough.yaml) for explicitly combined assessment. Honor explicit choices and record inferences. If the component is omitted, use unambiguous task/repository context.
2. Read [REVIEW-GUIDELINES.md](REVIEW-GUIDELINES.md) in full and the selected profile. For thorough, read its three named profiles and take maximum applicable depths. Missing mandatory framework resources are a setup limitation; do not silently substitute a weaker method.
3. Load the persistent GR4 references: [repositories](project/repositories.md), [architecture](project/architecture.md), [build](project/build.md), [testing](project/testing.md), and [policies](project/policies.md). Resolve the requested GR4 repository using the superbuild manifest and configured source paths; verify identity and preserve local changes. Follow relevant source citations when a fact matters to the reviewed change.
4. Discover PR head/base metadata, actual comparison, evidenced parent and inherited changes, ultimate destination, cross-repository prerequisites, source/artifact identities and applicable checks. Pin revisions and preserve metadata source/time. Use the project-controlled SDK and superbuild with `GR4_BUILD_PARALLEL_LEVEL=4`. A stale installed artifact cannot stand in for a reviewed component. Resolve routine facts autonomously; ask only for a material ambiguity that survives available evidence, while continuing independent work.
5. Create a unique run directory at `<superbuild>/.work/reviews/<run-id>/`, where the run ID identifies the component, PR or target, pinned head, and invocation. Generate [review-contract.yaml](templates/review-contract.yaml) and a [candidate ledger](templates/candidate-ledger.md) there. Keep disposable sources, worktrees, build trees, install prefixes, probes, and logs under that run directory's `work/` subdirectory; do not use `/tmp` for review work. Record framework/project-reference identity, comparison/dependency state, environment, checks and limitations. Use the [contract schema](schemas/review-contract.schema.json); `ready` means comparison identity is established, not merge readiness.
6. Understand the change, read the [dimension index](dimensions/index.yaml), select applicable dimensions/depth from the profile and risk, and load those dimension files. Honor profile exclusions before applying default depths or risk escalation: maintainer reviews exclude cybersecurity (`security-trust`) unless explicitly requested. Record a bounded plan. Run the smallest discriminating checks; broaden for affected integration, required obligations or new evidence within scope.
7. Apply the shared review method. Maintain the ledger, perform the mandatory disproof pass for every serious candidate, consolidate root causes, attribute inherited behavior correctly, and classify only supported claims. All profiles use one evidence standard.
8. Produce [REVIEW.md](templates/review-report.md) alongside the contract, ledger and referenced evidence. Apply stopping and freshness rules; report technical assessment, integration state and obligations separately. A successful review may produce zero findings. Review completion is distinct from merge readiness.

Review authority does not authorize production edits, publication, approvals, commits, pushes or merges. Follow actual task/host authority for checks and isolated probes. Do not load historical design documents or retrospective findings for a fresh review.
